# Verification checklist

This checklist records the stated responsibility of every module in `src/lettia/`, the observable behaviors each module promises, and the test or typing-fixture evidence proving each behavior (or `GAP` where no automated assertion exists). `tests/architecture/test_verification_checklist.py` enforces that `spec/verification.md` stays in step with `src/` and `tests/`.

## How to use

1. **Automated gates.** Run the CI quality checks before merging:
   ```bash
   uv sync --locked --all-extras
   uv run ruff format --check src tests benchmarks examples
   uv run ruff check src tests benchmarks examples
   uv run pyrefly check
   uv run pyright
   uv run mypy
   uv run pytest
   uv run lettia openapi export examples.users_api:app --output examples/openapi.json
   git diff --exit-code examples/openapi.json
   ```
   Package validation runs `uv build` and `uvx --from twine twine check dist/*`. For performance-sensitive changes, also run `uv run python -m benchmarks.run_benchmark` (and `uv run python -m benchmarks.run_server_benchmark` for server-loop numbers).
2. **Reviewing a change.** For each modified `src/lettia/**.py`, read its section below and the `GLOBAL` items. When a behavior changes, update the item's claim and evidence in the same change. When a new behavior is added, append the next unused number in that section. When a behavior is removed, delete its item; never reuse deleted numbers.
3. **Full audit.** Walk every section in order. Open each referenced test function or typing fixture and confirm its assertions prove the claim as written. Confirm each claim against the cited documentation or docstrings. Record contradictions under `## Open findings`, and replace `GAP` items with test references when tests are added.

## Evidence rules

Each item inside `## Global invariants` or a module section must use this single-line format:

```markdown
- [ ] <ID>: <claim> Evidence: <evidence>
```

- **Evidence references:** Either a comma-separated list of backticked node IDs (`tests/<path>.py::<test_function>`, with optional `[param-id]` only when the claim covers a single parametrized case) or typing fixtures (`tests/typing/positive/<fixture>.py` or `tests/typing/negative/<fixture>.py`), or `GAP (<what is unproven and how it is currently assured, if at all>)` with no nested parentheses.
- **Assertion requirement:** A test counts as evidence only if an assertion inside it checks the claimed outcome; executing a path without asserting the outcome does not qualify.
- **Claim granularity:** State one observable behavior per item as condition -> outcome (status code, exception type and message fragment, header, returned value, startup problem text, or emitted log field).
- **Section bullets:** Every bullet inside `## Global invariants` and inside a module section must be a checklist item; place context in `Responsibility:` or `Docs:`.
- **Coverage dimensions:** Check every module against all dimensions promised in docs or docstrings: primary responsibility, input validation and error paths, boundary values, security-relevant behavior (header/cookie injection, path traversal, untrusted proxy headers, guard-before-decode), resource cleanup (close, teardown, cancellation), registration-time vs request-time work, and public exports.
- **Item IDs:** `<PREFIX>-NN`, where `<PREFIX>` is derived from `src/lettia/<path>.py` by taking the path parts relative to `src/lettia`, dropping `.py`, stripping leading/trailing `_`, replacing `_` with `-`, uppercasing, and joining with `-` (two-digit `NN` starting at `01`).
